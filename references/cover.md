# 封面设计（punk-cover 方法 + codex 生图）

为文章生成高转化公众号封面图。**封面提示词用 punk-cover 方法生成，生图走 codex CLI**（grok 为纯文本模型、不能生图，见下方实测结论）。

## 封面提示词生成（调用 punk-cover）

1. **读 punk-cover 技能**：`~/.workbuddy/skills/punk-cover/SKILL.md`、`references/style-catalog.md`（风格目录）、`references/cover-prompt-blueprint.md`（封面提示词蓝图）。
2. **平台固定**：微信 2.35:1，不询问。
3. **选风格（自动）**：按内容题材从 styles 库自动选 1 个合适风格，不交互确认：
   - AI / 科技 / 产品 / 行业 / 分析 → `business-magazine-front-page`、`midcentury-surreal-editorial-cover`、`black-midcentury-modernist-cover`、`retro-torn-collage` 中选 1
   - 其他 → 按 `style-catalog.md` 的启发式选（business/report 风格用于行业内容，journal/concept 用于机制类内容）
   - 只用 `META.md` 中 `outputs` 含 `cover` 或 `poster` 的风格
4. **读所选风格**：`~/.workbuddy/styles/{style-id}/META.md` + `STYLE.md`，提取不可妥协的视觉锚点（材料、空间逻辑、标题处理、排版行为、纹理、配色、负面约束）。
5. **按蓝图编译整合式提示词**：以 `cover-prompt-blueprint.md` 为结构（role → 输入字段 → 内容理解 → 风格应用 → 构图 → 图文关系 → 排版 → 配色/材质/纹理 → 负面约束 → 最终标准），把所选风格的锚点**融入每一个封面决策**，输出一段完整连贯的封面生成提示词（不是"封面指令 + 风格指令"的拼接）。
6. **硬要求（缺一不可）**：
   - **封面不画任何文字**：不画主标题、不画副标题、不画英文小注、不画 LOGO / 水印 —— 标题文字由公众号平台在封面之外显示，画进图里会与平台标题重复且易出错字。提示词必须显式写明 `NO TEXT, NO LETTERS, NO WORDS, NO NUMBERS, NO LOGOS, NO WATERMARKS`，并在负面约束里重复一遍。
   - **具体视觉主体**：可辨识、有冲击力（机器人、人物、场景特写等），禁止纯抽象符号拼贴
   - **高对比配色**：主色 + 撞色/亮色点缀
   - 比例 2.35:1
7. **主题优先级（2026-09-21 起生效）：优先画"对普通人的利好"**
   - **首选画面**：普通人获得好处、变轻松、省事省钱的场景——例如学生用手机录课自动整理笔记、上班族一键把会议录音变成文档、创作者用新工具更快做出图/视频、普通人用上原本很贵的能力。
   - **画面要落到"人与结果"上**：一个人 + 明确的使用场景 + 可见的收益（清爽的笔记、完成的作品、省下的时间），而不是厂商 logo、模型参数或机器本身。
   - **只有当天主角新闻确实没有利好面**（如纯维权、纯事故、纯诉讼）时，才画"提醒/风险"向画面：普通人保住自己的东西（护住文件、锁上门、看清风险），基调克制，不做恐怖化处理。
   - **禁止**：抽象符号拼贴（盾牌、节点、分界线、数据流堆叠）；与内容无关的炫技科幻场景。
   - 画面的取材仍取当天主角新闻简写所指的那件事（如"免费了""不用手抄了"的那个场景），只是**用画面讲、不用文字写**。

## 生图路由

> **前置：网络出口**。codex 的生图接口在境外（`chatgpt.com`），**必须先确认代理可用**，否则 CLI 会静默挂起（实测可挂 50 分钟无任何输出，看起来像"CLI 坏了"）。
> 本机 v2rayN / xray 的可用入口是 **SOCKS5 `socks5h://127.0.0.1:10808`**（端口由 v2rayN 启动时决定，会变；用前先探测 xray.exe 的监听端口）。生图前先跑：
> ```bash
> export HTTPS_PROXY=socks5h://127.0.0.1:10808 HTTP_PROXY=socks5h://127.0.0.1:10808 ALL_PROXY=socks5h://127.0.0.1:10808
> curl -s -o /dev/null -w "%{http_code}\n" --max-time 20 -x socks5h://127.0.0.1:10808 https://chatgpt.com/
> ```
> 返回 403 / 421 等任何 HTTP 状态码都说明链路通；返回 `000` 则是网络不通，**不要启动生图**，直接告知用户。

### 优先：codex CLI

```bash
export HTTPS_PROXY=socks5h://127.0.0.1:10808 HTTP_PROXY=socks5h://127.0.0.1:10808 ALL_PROXY=socks5h://127.0.0.1:10808
cat prompt.txt | codex exec --skip-git-repo-check --cd "<输出目录>" > codex.log 2>&1
```

- **必须加 `--skip-git-repo-check`**；**不要加 `-m gpt-image-2`**（ChatGPT 订阅不支持）。
- **长提示词用管道喂 stdin**（`cat prompt.txt | codex exec …`）。若把长 prompt 直接当参数传、又在后台运行，codex 会打印 `Reading additional input from stdin...` 后一直等待，看起来像卡死。
- 判定失败：退出码非 0、输出文件不存在、或报「usage limit / You've hit your usage limit」（订阅额度用尽，会给出恢复时间）。**注意：判定超时前先读下方实测结论第 1 条**——codex 常"看起来无响应"但最终会产出。

### 实测结论：grok 不能作为生图降级路径（2026-08-31 / 2026-09-22 两次实测）

`grok -p "…生图提示词…"` **不会产出图片文件**——grok CLI 是纯文本模型，只会回一段文字描述，不落盘图片（2026-08-31 实测跑 6 分钟失败）。**不要再把 grok 当作 codex 的降级生图方案**，否则会白等一轮。

> 注意区分：grok 走同一个 socks5 代理**做文本任务是正常的**（2026-09-22 实测 `grok -p "回答四个字：代理可用"` 正常返回）。它缺的是生图能力，不是网络能力。

codex 真正失败（usage limit / 明确报错）时的正确处置顺序：

1. **先查目录再判定失败**：codex 常出现「日志长时间无新输出、但进程仍在后台合成」的情况，实测最终会产出 `cover.png`（2026-08-31 案例：无响应 >7 分钟，降级前查目录发现图片已生成）。**判定超时前务必确认进程已退出、且目标目录确实没有新文件**，也不要贸然 kill 进程树。
2. 确认 codex 无法产出后，向用户报告并保留已完成的 HTML 稿件，等网络/额度恢复后补封面；微信草稿支持后补封面。
3. 若用户另指定了可用的生图服务，再按其方式生成。

## 生成后校验

- 文件存在 + 实际宽高比接近 2.35:1。
- **画面内无任何文字 / 字母 / 数字 / LOGO / 水印**（有则重生成）。
- 有明确视觉主体、配色有对比、有纵深感、风格统一。

## 兜底

punk-cover / styles 文件缺失时，按硬要求（**无文字** + 具体主体 + 高对比配色 + 2.35:1）自行生成提示词。

## 使用

- 排版后、推送前生成（供 `publish.cjs --cover` 使用）。
- 封面只出画面、不出文字，因此与 `--title` 之间不存在"文字重复"问题；画面取材呼应 `--title` 的核心场景即可。
