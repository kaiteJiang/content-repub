# AI 新闻日更（AIHOT 源）

每天两次（08:30 / 17:30）从 AIHOT 抓取有价值的 AI 相关新闻，**进入原文逐条详细解读**，重点从「行业发展」与「利他」两个角度独立发表看法，再进入 content-repub 的去 AI 味 → 排版 → 推送流程。**同一 URL 不重复推送**。

解读以原文为准，不基于 AIHOT 摘要；只有原文确实无法获取时才降级到摘要并明确标注。

## 一、抓取

匿名只读 API，无需 Key：

```text
GET https://aihot.news/api/v1/items?mode=selected&window=24h&limit=15
```

- 抓 `limit=15` 再挑选，不要只抓 3—5 条。
- 请求头 User-Agent 带 Actor 标识：读取本机 `~/.workbuddy/skills/aihot/.aihot-actor-id`，内容为合法 UUID v4 时 User-Agent 追加 `aihot-actor/<uuid>`；否则用基础 UA `aihot-skill/1.6.0 (+https://aihot.news/aihot-skill/)`。
- 只连 `https://aihot.news/api/v1/*`，不索要 key/cookie/账号。旧域名 `https://aihot.virxact.com/api/v1/*` 是官方长期保留的兼容入口，仍可读取，但默认走新域名。
- **Windows 坑**：`curl -o` 直接写入含中文的路径会报 exit 23（write error），改用 shell 重定向 `curl -s "URL" > /e/workbuddy/tmp_xxx/sel.json` 存到 ASCII 路径再解析。
- 默认 `window=24h`。

字段（展示前判空）：`title`、`summary`、`reason`、`source.name`、`category`、`score`、`links.original`（第三方原文）、`links.aihot`（站内阅读页，仅摘要+推荐理由，**无全文**）。

## 二、挑选 3—5 条（含去重与补齐）

**去重**：运行前读取 `~/.workbuddy/skills/content-repub/.published.json`（不存在视为空），排除 `links.original` 或 `links.aihot` 已出现在清单中的条目，**绝不重复推送**。

**补齐**：当天精选（`mode=selected`）排除已推送后不足 3 条时，用 `mode=all` 再抓一次（`/api/v1/items?mode=all&window=24h&limit=20`）从 AI 动态全量池补齐，并在结果中注明「精选不足，已从全量动态补齐」。

挑选优先级：

1. **优先选 `links.original` 可抓原文的条目**：官方博客／媒体站与 X 帖子。公众号（`mp.weixin.qq.com`）原文被微信验证墙拦截、免费抓不到正文，仅在确需时选 1 条并接受降级解读
2. `reason` 非空（有明确价值点）
3. 与行业发展强相关（模型/产品/行业/论文/技巧）
4. `score` 较高（参考 ≥65）
5. 主题多元，避免同类别或同公司堆叠
6. 最终 3—5 条

## 三、逐条抓原文（核心）

对每条，按 `links.original` 抓正文，按以下顺序尝试：

1. `x.com/.../status` 帖子 → 用 `references/parse_tweet.md` 的 Python 代码抓帖子正文
2. 其他网页 → WebFetch 抓正文（返回标题 + 全部正文段落 + 关键数字）
3. **WebFetch 失败时 → 用 `anything-md.doocs.org` 兜底**：`POST https://anything-md.doocs.org/`，body `{"url": "<原文URL>"}`，请求头 `Content-Type: application/json` + `User-Agent: curl/8.0`，响应 JSON 的 `markdown` 字段即正文（对普通网页有效，实测可抓 anthropic 等站点）
4. `mp.weixin.qq.com` → 免费途径（WebFetch 与 anything-md 均返回微信验证墙/空壳）抓不到正文，直接判定不可抓，不要反复重试

原文抓取失败的降级顺序：

1. 抓 `links.aihot` 站内阅读页（只有「AI 导读」+「推荐理由」，无全文）
2. 仍无正文 → 基于 `summary` + `reason` 解读，**并在该条开头明确标注「⚠️ 原文未能获取，以下基于 AIHOT 摘要，可能与原文有出入」**

不要为了"每条都有原文"而编造正文或引用不存在的细节。

## 四、逐条解读（面向普通读者，白话优先）

动笔前先回答四个问题，答案决定写法：

1. **谁会看**：对 AI 感兴趣、但不写代码不读论文的普通读者——上班族、产品/运营、创业者、学生。他们花两三分钟看一篇，只想快速知道"今天 AI 圈发生了什么、跟我有什么关系"。
2. **想看什么影响**：不是技术架构，而是"会不会影响我的工作/钱/生活"——该换什么工具、哪个要涨价、哪个能省事、有什么坑、趋势往哪走。
3. **太专业怎么办**：术语第一次出现必须用一句话翻译；数字给参照（如"88B token"→"约等于 88 亿个词"）；少用英文缩写，必须用时括号配中文。
4. **能学会什么**：每条结尾必须有一个"能带走"的具体东西——工具 / 做法 / 判断标准 / 避坑提醒，让读者看完能对别人说一句"XX 发生了，记得去 YY"。

据此，每条写成「**新闻本体 + 虾解读**」两部分：

- **新闻本体（第 1 段）**：客观陈述新闻发生了什么——谁做了什么、什么结果、关键数字，白话讲清、术语翻译、数字给参照，不堆砌、不喊口号、不加个人观点。
- **「虾解读：」标记**：新闻本体之后放小标题「虾解读：」，作为解读内容的起始。
- **解读（第 2—3 段）**：我的观点——这件事对普通读者的实际影响（工作 / 钱包 / 日常 / 要避的坑），以及一个"能带走"的具体落点（工具 / 做法 / 判断标准 / 避坑提醒）。

解读段落之间用「所以…」「说白了…」「别以为…」这类口语化衔接，读起来像在跟朋友转述，而不是模板填表。

写作要求：

- **以原文为依据**，观点独立于 AIHOT 的 `reason`（`reason` 只作线索，不照搬）。
- 默认"对普通读者有用"为第一优先级；纯技术 / 纯公司战略的行业分析不再单列，确有影响时用白话融进去。
- 克制：不确定就写"尚待观察""建议关注"，不喊口号、不吹涨、不标题党。
- 引用数字 / 政策 / 原话时标注来源，并提醒读者回原文核对。
- 每条控制在 150—250 字左右，别写成小论文。

## 五、组装

- 汇总成 `article.md`：开头一句导语（今天 AI 圈值得关注的 N 件事），再逐条展开
- 每条标题链接 `links.aihot`；原文出处附 `links.original`
- **不加 AIHOT 来源声明**（个人匿名使用，无需署名）
- **不加自我广告**：不生成「我是 XX / 欢迎关注 / 点赞·在看·转发三连」等作者签名与引导语，正文到收束为止

### 排版约定（AI 日报专用）

- **不生成封面卡片**（主题组件库里的「AI 圈日报 / 每日 AI 信号速读」那个开头大卡）：公众号封面已由单独上传的封面图承担，正文从导语一句 + 亮点卡直接开始，不再放封面模块。
- **章节标题不带英文副标题小字**：组件里的「PART 01 + 英文翻译」样式取消，只保留编号 + 中文标题一行。
- **新闻本体与解读分区**：每条先写「新闻本体」段落（客观陈述新闻事实），再放小标题「虾解读：」（黄色下划线样式），后面接解读段落（观点 / 影响 / 能带走）。固定结构：「新闻标题 → 新闻本体 → 虾解读： → 解读」。
- **正文自然段落首行缩进 2 字**：非标题的正文段落加 `text-indent: 2em`（首行缩进 2 个汉字，约 4 个半角字符宽）；原文链接脚注行不缩进。
- 其余按主题组件库装配，收束到结语结束。

## 六、去重记录与后续流程

**推送成功后**，把本次各条的 `links.original`（无则用 `links.aihot`）追加到 `~/.workbuddy/skills/content-repub/.published.json`（JSON 对象 `{"items": [{"url": "...", "ts": "ISO 时间"}]}`，保留最近 7 天），供下次运行去重。

- 组装好的 `article.md` 直接作为 content-repub 第 2 步输入，走「去 AI 味二创 → 公众号排版 → 推送草稿」
- 用户单独发了链接时：X 帖子 → `parse_tweet.md`；其他网页 → WebFetch（失败用 anything-md 兜底）；单独链接条数不足 3—5 条时用 AIHOT 补足
- 推送照旧（`references/publish.md`，微信凭据已配置）

## 安全与合规

- 只连 `https://aihot.news/api/v1/*` 匿名只读接口（`https://aihot.virxact.com/api/v1/*` 为官方长期保留的兼容入口）
- `anything-md.doocs.org` 是开源 URL→Markdown 服务，仅用于抓取公开网页正文；抓第三方原文时遵守其版权，解读用自己的话概括+评述，不整段搬运
- 个人非商业、公益非商业、组织内部使用免费；面向外部的商业产品/收费/转售/公开镜像须先取得 AIHOT 书面授权
